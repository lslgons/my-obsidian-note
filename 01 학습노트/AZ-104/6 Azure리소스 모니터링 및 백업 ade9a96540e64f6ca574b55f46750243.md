# 6. Azure리소스 모니터링 및 백업

# 1) 파일 및 폴더백업 구성

## **Azure Backup**

**Azure Backup**
은 Microsoft 클라우드에서 데이터를 백업(또는 보호)하고 복원하는 데 사용할 수 있는 Azure 기반 서비스입니다. 기존의 온-프레미스 또는 오프사이트 백업 솔루션을 신뢰할 수 있고 안전하며 가격 경쟁력이 있는 클라우드 기반 솔루션으로 대체합니다.

- **온-프레미스 백업 오프로드**. 온-프레미스 리소스를 클라우드에 백업할 수 있는 간단한 솔루션을 제공합니다. 복잡한 온-프레미스 백업 솔루션을 배포할 필요 없이 장단기 백업을 수행합니다.
- **Azure IaaS VM 백업**. 실수로 데이터가 삭제되지 않도록 방지하기 위해 독립적이고 격리된 백업을 제공합니다. 구성 및 확장성이 간단하고, 백업이 최적화되어 있으며, 필요에 따라 쉽게 복원할 수 있습니다.
- **무제한 데이터 전송**. 사용자가 전송하는 인바운드 또는 아웃바운드 데이터의 양을 제한하거나, 전송되는 데이터에 대해 요금을 부과하지 않습니다.
- **안전한 데이터 유지**. 데이터 암호화를 통해 퍼블릭 클라우드에서 데이터를 안전하게 전송하고 스토리지할 수 있습니다.
- **애플리케이션 일치 백업 가져오기**. 애플리케이션 일치 백업은 백업 복사본을 복원하는 데 필요한 모든 데이터가 복구 지점에 있음을 의미합니다. Azure Backup에서 애플리케이션 일치 백업을 제공하므로 데이터를 복원하기 위한 추가 수정 프로그램이 필요하지 않습니다.
- **단기 및 장기 데이터 보존**. 단기 및 장기 데이터 보존을 위해 Recovery Services 자격 증명 모음을 사용할 수 있습니다. Azure는 Recovery Services 자격 증명 모음에 데이터를 유지할 수 있는 기간을 제한하지 않습니다.
- **자동 스토리지 관리**. 일부는 온-프레미스, 일부는 클라우드인 하이브리드 환경에는 종종 다른 유형의 스토리지가 필요합니다. Azure Backup은 백업 스토리지를 자동으로 할당하고 관리하며, 종량제 모델을 사용하므로 사용한 스토리지 비용만 지불하면 됩니다.
- **여러 스토리지 옵션**. Azure Backup은 스토리지/데이터의 고가용성을 유지하는 두 가지 유형의 복제를 제공합니다.
    - LRS(로컬 중복 스토리지)는 데이터 센터의 스토리지 배율 단위로 데이터를 세 번 복제합니다(세 개의 데이터 복사본을 만듦). 모든 데이터 복사본은 동일한 지역 내에 있습니다. LRS는 로컬 하드웨어 오류로부터 데이터를 보호하기 위한 저비용 옵션입니다.
    - GRS(지역 중복 스토리지)는 기본값이며 권장되는 복제 옵션입니다. GRS는 데이터 원본의 기본 위치에서 수백 마일 떨어진 보조 지역으로 데이터를 복제합니다. GRS는 LRS보다 많은 비용이 소요되지만 GRS는 지역 가동 중단이 발생해도 높은 수준의 데이터 내구성을 제공합니다.

## **Azure Backup 센터 구현**

Backup 센터에서는 Azure에서 기업이 대규모 백업을 제어, 모니터링, 운영, 분석하는 데 사용할 수 있는 단일 통합 관리 환경을 제공합니다. 따라서 Azure의 기본 관리 환경과 일치합니다.

## **Recovery Services 자격 증명 모음**

Recovery Services 자격 증명 모음은 IaaS VM(Linux 또는 Windows) 및 Azure SQL 데이터베이스와 같은 다양한 Azure 서비스의 백업 데이터를 저장합니다. Recovery Services 자격 증명 모음은 System Center DPM, Windows Server, Azure Backup Server 및 기타 서비스를 지원합니다. Recovery Services 자격 증명 모음을 사용하면 관리 오버헤드를 최소화하면서 백업 데이터를 쉽게 구성할 수 있습니다.

Recovery Services 자격 증명 모음을 사용하여 Azure 파일 공유를 백업할 수 있습니다.

Recovery Service 자격 증명 모음을 사용하여 온-프레미스 파일 및 폴더를 백업할 수도 있습니다.

## **온-프레미스 파일 및 폴더 백업 구성**

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%201.png)

1. **Recovery Services 자격 증명 모음을 만듭니다**. Azure 구독 내에서 백업에 대한 복구 서비스 자격 증명 모음을 만들어야 합니다.
2. **에이전트 및 자격 증명 파일을 다운로드합니다**. Recovery Services 자격 증명 모음은 Azure Backup 에이전트를 다운로드하는 링크를 제공합니다. Backup 에이전트가 로컬 머신에 설치됩니다. 에이전트를 설치하는 동안 필요한 자격 증명 파일도 있습니다. 에이전트의 최신 버전이 있어야 합니다. 에이전트를 제거하고 다시 설치하여 2.0.9083.0 미만의 에이전트 버전을 업그레이드해야 합니다.
3. **에이전트 설치 및 등록**. 설치 관리자가 설치 위치, 프록시 서버 및 암호 정보를 구성하는 마법사를 제공합니다. 다운로드한 자격 증명 파일은 에이전트를 등록하는 데 사용됩니다.
4. **백업 구성** 에이전트를 사용하여 백업 시기, 백업할 항목, 항목을 보존하는 기간 및 네트워크 제한과 같은 설정을 포함한 백업 정책을 만듭니다.

# 2) 가상머신 백업구성

## **가상 머신 데이터 보호**

정기적으로 백업을 수행하여 데이터를 보호할 수 있습니다. 사용 사례에 따라 VM에 사용 가능한 여러 백업 옵션이 있습니다.

### **Azure Backup**

프로덕션 작업을 실행하는 Azure VM을 백업하려면 Azure Backup을 사용합니다. Azure Backup은 Windows와 Linux VM 모두에 대해 애플리케이션 일치 백업을 지원합니다.

### **Azure Site Recovery**

Azure Site Recovery는 주요 자연재해 또는 광범위한 서비스 중단으로 인해 전체 지역에서 중단이 발생하는 주요 재해 시나리오에서 VM을 보호합니다.

### **관리 디스크 스냅샷**

개발 및 테스트 환경에서 스냅샷은 Managed Disks를 사용하는 VM을 백업하기 위한 빠르고 간단한 옵션을 제공합니다. 관리 디스크 스냅샷은 기본적으로 표준 관리 디스크로 저장되는 관리 디스크의 완전한 읽기 전용 복사본입니다. 스냅샷을 사용하면 관리 디스크를 언제든지 백업할 수 있습니다.

## **가상 머신 스냅샷 만들기**

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%202.png)

복구 지점은 두 단계가 모두 완료된 후에만 만들어지는 것으로 간주됩니다. 업그레이드의 일환으로, 스냅샷이 완료되는 즉시 복구 지점이 생성됩니다.

- 자격 증명 모음으로의 데이터 전송이 완료될 때까지 기다리지 않고 백업 작업의 일부로 만든 스냅샷을 복구에 사용할 수 있습니다.
- 기본적으로 스냅샷을 로컬에 2일 동안 보존하여 백업 및 복원 시간을 단축합니다. 이 기본 스냅샷 보존 값은 1일에서 5일 사이의 값으로 구성할 수 있습니다.
- 최대 32TB까지 디스크 크기를 지원합니다. Azure Backup에서는 디스크 크기를 조정하지 않는 것이 좋습니다.
- 표준 HDD 디스크 및 프리미엄 SSD 디스크와 함께 표준 SSD 디스크를 지원합니다.
- 증분 스냅샷은 페이지 Blob으로 저장됩니다. 비관리 디스크를 사용하는 모든 사용자의 경우 로컬 스토리지 계정에 저장된 스냅샷에 대한 요금이 청구됩니다. 관리형 VM 백업에서 사용하는 복원 지점 컬렉션이 기본 스토리지 수준에서 Blob 스냅샷을 사용하므로 관리 디스크의 경우 Blob 스냅샷 가격 책정에 해당하는 비용이 표시되고 증분됩니다.
- Premium Storage 계정의 경우, 빠른 복구 지점에 대해 만든 스냅샷이 10TB의 할당된 공간 한도에 포함됩니다.
- 복원 요구 사항을 기준으로 스냅샷 보존을 구성할 수 있습니다. 요구 사항에 따라, 아래에 설명된 대로 백업 정책 블레이드에서 스냅샷 보존을 최소 1일로 설정할 수 있습니다. 이렇게 하면 복원을 자주 수행하지 않는 경우 스냅샷 보존 비용 절감에 도움이 됩니다.

## **가상 머신 Backup**

1. **Recovery Services 자격 증명 모음 만들기**. 파일과 폴더를 백업하려면 데이터를 저장하려는 지역에 Recovery Services 자격 증명 모음을 만들어야 합니다. 또한 스토리지 복제 방법을 지역 중복(기본값) 또는 로컬 중복 중에서 결정해야 합니다. 기본적으로 사용자 자격 증명 모음에는 지역 중복 스토리지가 있습니다.
2. **Portal을 사용하여 백업 정의**. 정의된 간격으로 데이터의 스냅샷을 찍어 데이터를 보호합니다. 이러한 스냅샷은 복구 지점이라고 하며 복구 서비스 자격 증명 모음에 저장됩니다. VM을 복구하거나 다시 빌드해야 하는 경우 또는 그 때에 저장된 복구 지점 중 하나에서 VM을 복원할 수 있습니다.
3. **가상 머신 백업**. Azure VM 에이전트는 작업할 백업 확장을 위한 Azure 가상 머신에 설치되어야 합니다. 그러나 Azure 갤러리에서 VM을 만든 경우 VM 에이전트는 이미 가상 컴퓨터에 있습니다. 온-프레미스 데이터 센터에서 마이그레이션한 VM에는 VM 에이전트가 설치되어 있지 않습니다.

## **가상 머신 복원**

가상 머신 스냅샷이 Recovery Services 자격 증명 모음에 안전하게 저장되면 쉽게 복구할 수 있습니다.

![](https://docs.microsoft.com/ko-kr/learn/wwl-azure/configure-virtual-machine-backups/media/virtual-machine-restore-876df613.png)

복원 작업을 트리거하면 Backup 서비스는 복원 작업을 추적하기 위한 작업을 만듭니다. 또한 백업 서비스를 통해 알림을 생성하고 일시적으로 표시하므로 백업 진행 방식을 모니터링합니다.

## **Azure Backup Server 구현**

가상 머신을 백업하는 또 다른 방법은 DPM(Data Protection Manager) 또는 MABS(Microsoft Azure Backup Server) 서버를 사용하는 것입니다. 이 방법은 특수 워크로드, 가상 머신 또는 파일, 폴더, 볼륨에 사용할 수 있습니다. 특수 워크로드에는 SharePoint, Exchange 및 SQL Server가 포함될 수 있습니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%203.png)

1. 보호하려는 머신에 DPM 또는 MABS 보호 에이전트를 설치합니다. 그런 다음, DPM 보호 그룹에 컴퓨터를 추가합니다.
2. 온-프레미스 머신을 보호하려면 DPM 또는 MABS 서버가 온-프레미스에 있어야 합니다.
3. Azure VM을 보호하려면 Azure VM으로 실행되는 MABS 서버가 Azure에 있어야 합니다.
4. DPM/MABS를 사용하여 백업 볼륨, 공유, 파일 및 폴더를 보호할 수 있습니다. 또한 컴퓨터의 시스템 상태/완전 복구를 보호하고 특정 앱을 앱 인식 백업 설정으로 보호할 수 있습니다.
5. DPM/MABS에서 컴퓨터 또는 앱에 대한 보호를 설정할 때 단기 스토리지용 MABS/DPM 로컬 디스크에 백업한 다음, 온라인 보호를 위해 Azure에 백업하도록 선택합니다. 로컬 DPM/MABS 스토리지에 백업을 실행할 시기와 Azure에 온라인 백업을 실행할 시기도 지정합니다.
6. 보호된 워크로드의 디스크는 지정한 일정에 따라 로컬 MABS/DPM 디스크에 백업됩니다.
7. DPM/MABS 디스크는 DPM/MABS 서버에서 실행되는 MARS 에이전트에 의해 자격 증명 모음으로 백업됩니다.

## **Azure Site Recovery 구현**

Site Recovery는 중단 기간 동안에도 비즈니스 앱과 워크로드를 유지하여 비즈니스 연속성을 보장합니다. Site Recovery는 물리적 컴퓨터와 VM(가상 머신)에서 실행되는 워크로드를 기본 사이트에서 보조 위치로 복제합니다. 기본 사이트에서 중단이 발생하면 보조 위치로 장애 조치(failover)하고 여기에서 앱에 액세스합니다. 기본 위치가 다시 실행되고 나면 해당 위치로 대체될 수 있습니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%205.png)

- Site Recovery를 사용하면 Azure Portal의 단일 위치로부터 복제, 장애 조치 및 장애 복구를 설정 및 관리할 수 있습니다.
- Site Recovery는 애플리케이션 데이터를 차단하지 않고 복제를 오케스트레이션합니다. Azure에 복제하면 데이터가 제공하는 복원력과 함께 Azure 스토리지에 저장됩니다. 장애 조치(failover)가 발생하는 경우 복제된 데이터를 기반으로 하여 Azure VM을 만듭니다.
- Site Recovery는 Azure VM 및 VMware VM에 대해 연속 복제를 제공하고 Hyper-V에 대해서는 짧은 빈도(30초)의 복제를 제공합니다.
- 애플리케이션 일치 스냅샷으로 복구 지점을 사용하여 복제할 수 있습니다. 이러한 스냅샷은 디스크 데이터, 메모리의 모든 데이터, 프로세스의 모든 트랜잭션을 캡처합니다.
- Site Recovery는 효율적인 네트워크 전환을 위한 IP 주소 예약, 부하 분산 장치 구성 또는 Azure Traffic Manager의 통합 등 간단한 애플리케이션 네트워크 관리를 위해 Azure와 통합됩니다.

# 4) **Azure 경고 구성**

## **Azure Monitor 경고 관리**

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%2011.png)

- **향상된 알림 시스템**. 모든 최신 경고는 여러 경고에서 다시 사용할 수 있는 알림 및 작업으로 명명된 그룹인 작업 그룹을 사용합니다.
- **통합 작성 환경**. Azure Monitor, Log Analytics, Application Insights 전체의 메트릭, 로그 및 활동 로그에 대한 모든 경고가 한 곳에서 생성됩니다.
- **Azure Portal에서 Log Analytics 경고 보기**. 이제 구독에서 Log Analytics 알림을 관찰할 수도 있습니다. 이전에는 별도의 포털에 있었습니다.
- **발생한 경고 및 경고 규칙의 분리**. 경고 규칙(경고를 트리거하는 조건의 정의)과 발생한 경고(경고 규칙 발생의 인스턴스)가 구별되므로 운영 및 구성 보기가 구분됩니다.
- **향상된 워크플로**. 새로운 경고 작성 환경은 알림을 받을 항목을 더 간단하게 검색할 수 있는 경고 규칙 구성 프로세스를 사용자에게 안내합니다.

### **경고 상태**

경고가 해결 과정에 있는지 지정하는 경고 상태를 설정할 수 있습니다. 경고 규칙에 지정된 조건이 충족되면 경고가 생성되거나 실행되고, 상태는 **새 경고**
입니다. 경고를 확인할 때 및 경고를 닫을 때 상태를 변경할 수 있습니다. 모든 상태 변경은 경고 기록에 저장됩니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%2012.png)

## **작업 그룹 만들기**

작업 그룹은 Azure 구독 소유자가 정의한 알림 기본 설정 컬렉션입니다. Azure Monitor 및 Service Health 경고는 작업 그룹을 사용하여 경고가 트리거되었음을 사용자에게 알립니다. 사용자의 요구 사항에 따라 다양한 경고가 동일한 작업 그룹을 사용할 수도 있고 서로 다른 작업 그룹을 사용할 수도 있습니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%2013.png)

- **Azure Resource Manager 역할에 메일 보내기** - 구독 역할의 멤버에게 메일을 보냅니다. 이메일은 해당 역할의 Azure AD 사용자 멤버에게만 전송됩니다. Azure AD 그룹 또는 서비스 주체에게는 이메일이 전송되지 않습니다.
- **메일/SMS 메시지/푸시/음성** - 메일, SMS, 푸시 또는 음성 작업을 지정합니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%2014.png)

- **Automation Runbook** - Automation Runbook은 시스템 및 네트워크 운영 프로세스를 지원하는 워크플로를 정의, 빌드, 오케스트레이션, 관리 및 보고하는 기능입니다. Runbook 워크플로는 애플리케이션, 데이터베이스 및 하드웨어와 같은 모든 유형의 인프라 요소와 잠재적으로 상호 작용할 수 있습니다.
- **Azure Functions** – Azure Functions는 인프라를 명시적으로 프로비저닝하거나 관리하지 않고도 이벤트 트리거 코드를 실행할 수 있는 서버리스 컴퓨팅 서비스입니다.
- **ITSM** – Azure와 지원되는 ITSM(IT 서비스 관리) 제품/서비스를 연결합니다. 이 경우 ITSM 연결이 필요합니다.
- **논리 앱** - 논리 앱은 워크플로를 자동화하여 중요 비즈니스용 앱과 서비스를 연결합니다.
- **웹후크** – 웹후크는 외부 애플리케이션이 시스템과 통신할 수 있도록 하는 HTTPS 또는 HTTP 엔드포인트입니다.

## 5) **Log Analytics 구성**

Log Analytics는 클라우드 및 온-프레미스 환경의 리소스에서 생성된 데이터를 수집 및 분석하도록 도와주는 서비스입니다.

로그 쿼리를 사용하면 Azure Monitor 로그에서 수집된 데이터를 유용하게 활용할 수 있습니다. 강력한 쿼리 언어를 사용하면 여러 테이블의 데이터를 조인하고, 큰 데이터 집합을 집계하고, 최소한의 코드로 복잡한 작업을 수행할 수 있습니다. 지원 데이터가 수집되는 동안 거의 모든 질문에 답변이 제공되고 분석되며, 올바른 쿼리를 구성하는 방법을 이해할 수 있습니다.

# 6) Network Watcher 구성

**Network Watcher**는 Azure 가상 네트워크의 리소스를 **모니터링**하고 **진단**하고 **메트릭**을 보고 **로그**를 사용하거나 사용하지 않도록 설정하는 도구를 제공합니다. Network Watcher는 네트워크 시나리오 수준에서 조건을 모니터링하고 진단할 수 있는 지역 서비스입니다.

![Untitled](6%20Azure%EB%A6%AC%EC%86%8C%EC%8A%A4%20%EB%AA%A8%EB%8B%88%ED%84%B0%EB%A7%81%20%EB%B0%8F%20%EB%B0%B1%EC%97%85/Untitled%2017.png)

- **IP 흐름 확인**: 인터넷 및 온-프레미스 환경에 대한 연결 문제를 신속하게 진단합니다.
- **다음 홉**: 다음 홉을 표시하여 트래픽이 의도한 대상으로 연결되는지 확인합니다. 이렇게 하면 네트워킹 라우팅이 올바르게 구성되었는지 확인하는 데 도움이 됩니다.
- **VPN 진단**: 게이트웨이 및 연결 문제를 해결합니다. VPN 진단은 다양한 정보를 반환합니다.
- **NSG 흐름 로그**: NSG 흐름 로그는 네트워크 보안 그룹을 통해 IP 트래픽을 매핑합니다.
- **연결 문제 해결**. Network Watcher 네트워킹 도구 및 기능 모음에 추가된 최신 기능입니다.
