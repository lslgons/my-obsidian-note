# Static Pods

- 스태틱 파드: kubelet이 직접 실행하는 파드
- 각각의 노드에서 kubelet에 의해 실행
- 파드들을 삭제할때 apiserver를 통해서 실행되지 않은 스태택 파드(static pod)는 삭제 불가
    - 즉, 노드의 필요에 의해 사용하고자 하는 파드는 스태틱 파드로 세팅
- 다음 명령어 들을 사용하여 실행하고자 하는 static pod의 위치를 설정 가능

![Untitled](kube-system%20%EC%BB%B4%ED%8F%AC%EB%84%8C%ED%8A%B8/Untitled%203.png)

## Static Pods의 기본경로

- 기본 경로는 /etc/kubernetes/manifests
- 이미 쿠버네티스 시스템에서는 필요한 기능을 위해 다음과 같은 스태틱 파드를 사용
- 각각의 컴포넌트의 세부 사항을 설정할 때는 여기 있는 파일들을 수정하면 자동으로 업데이트돼
파드를 재구성
- 파드의 작성 요령은 기존의 파드와 동일하나 해당경로에 위치하여야 함

```yaml
# vim /etc/kubernetes/manifests/static-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: static-web
  labels:
    role: myrole
spec:
  containers:
    - name: web
      image: nginx
      ports:
        - name: web
          containerPort: 80
          protocol: TCP
```

etcd 매니페스트 파일 확인

```bash
$ sudo cat /etc/kubernetes/manifests/etcd.yaml 
apiVersion: v1
kind: Pod
metadata:
  annotations:
    kubeadm.kubernetes.io/etcd.advertise-client-urls: https://10.128.0.30:2379
  creationTimestamp: null
  labels:
    component: etcd
    tier: control-plane
  name: etcd
  namespace: kube-system
spec:
  containers:
  - command:
    - etcd # 바이너리 
    - --advertise-client-urls=https://10.128.0.30:2379 # 포트번호
    - --cert-file=/etc/kubernetes/pki/etcd/server.crt  # server.crt
    - --client-cert-auth=true
    - --data-dir=/var/lib/etcd                         # etcd 저장소
    - --initial-advertise-peer-urls=https://10.128.0.30:2380
    - --initial-cluster=instance-1=https://10.128.0.30:2380
    - --key-file=/etc/kubernetes/pki/etcd/server.key   # server.key
    - --listen-client-urls=https://127.0.0.1:2379,https://10.128.0.30:2379
    - --listen-metrics-urls=http://127.0.0.1:2381
    - --listen-peer-urls=https://10.128.0.30:2380
    - --name=instance-1
    - --peer-cert-file=/etc/kubernetes/pki/etcd/peer.crt
    - --peer-client-cert-auth=true
    - --peer-key-file=/etc/kubernetes/pki/etcd/peer.key
    - --peer-trusted-ca-file=/etc/kubernetes/pki/etcd/ca.crt
    - --snapshot-count=10000
    - --trusted-ca-file=/etc/kubernetes/pki/etcd/ca.crt # ca.crt
    image: k8s.gcr.io/etcd:3.5.0-0
    imagePullPolicy: IfNotPresent
    livenessProbe:
      failureThreshold: 8
      httpGet:
        host: 127.0.0.1
        path: /health
        port: 2381
        scheme: HTTP
      initialDelaySeconds: 10
      periodSeconds: 10
      timeoutSeconds: 15
    volumeMounts:
    - mountPath: /var/lib/etcd
      name: etcd-data
    - mountPath: /etc/kubernetes/pki/etcd
      name: etcd-certs
  hostNetwork: true
  priorityClassName: system-node-critical
  securityContext:
    seccompProfile:
      type: RuntimeDefault
  volumes:
  - hostPath:
      path: /etc/kubernetes/pki/etcd
      type: DirectoryOrCreate
    name: etcd-certs
  - hostPath:
      path: /var/lib/etcd
      type: DirectoryOrCreate
    name: etcd-data
status: {}
```

etcdctl을 사용해 etcd 서버로 요청하기

```bash
sudo ETCDCTL_API=3 ./etcdctl --endpoints 127.0.0.1:2379 \
                             --cacert=/etc/kubernetes/pki/etcd/ca.crt \
                             --cert=/etc/kubernetes/pki/etcd/server.crt \
                             --key=/etc/kubernetes/pki/etcd/server.key \
                             get / --prefix --keys-only
```

간단한 key 와 값 입력하기

```bash
sudo ETCDCTL_API=3 ./etcdctl --endpoints 127.0.0.1:2379 \
                             --cacert=/etc/kubernetes/pki/etcd/ca.crt \
                             --cert=/etc/kubernetes/pki/etcd/server.crt \
                             --key=/etc/kubernetes/pki/etcd/server.key \
                             put key1 value1
```

key1의 데이터 조회하기

```bash
sudo ETCDCTL_API=3 ./etcdctl --endpoints 127.0.0.1:2379 \
                             --cacert=/etc/kubernetes/pki/etcd/ca.crt \
                             --cert=/etc/kubernetes/pki/etcd/server.crt \
                             --key=/etc/kubernetes/pki/etcd/server.key \
                             get key1
```
