# 쿠버네티스 스토리지

# 1. Volume 개요

[Volumes | Kubernetes](https://kubernetes.io/docs/concepts/storage/volumes/)

- 컨테이너가 외부 스토리지에 액세스하고 공유하는 방법
- 파드의 각 컨테이너에 존재하는 고유의 파일시스템
- 파드의 컴포넌트로서 스펙에 의해 정의
- 독립적인 쿠버네티스 오브젝트가 아니며 스스로 생성, 삭제 불가

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled.png)

- emptyDir: 일시적인 데이터 저장, 비어 있는 디렉터리
- hostPath: 파드에 호스트 노드의 파일 시스템에서 파일이나 디렉토리를 마운트
- nfs: 기존 NFS (네트워크 파일 시스템) 공유가 파드에 장착
- gcePersistentDisk: 구글 컴퓨트 엔진 (GCE) 영구디스크 마운트 (awsElasticBlockStore, azureDisk 또한 클라우드에서 사용하는 형태)
- persistentVolumeClaim: 사용자가 특정 클라우드 환경의 세부 사항을 모른 채 GCE PersistentDisk 또는 iSCSI 볼륨과 같은 내구성 스토리지를 요구(Claim)할 수 있는 방법
- configMap, Secret, downwardAPI: 특수한 유형의 볼륨

# 3. hostPath

- 노드의 파일 시스템에 있는 특정 파일 또는 디렉터리 지정
- 영구 스토리지
- 다른 노드의 파드끼리 데이터 공유는 안됨

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled%202.png)

hostpath-httpd.yaml

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: hostpath-http
spec:
  containers:
  - image: httpd
    name: web-server
    volumeMounts:
    - name: html
      mountPath: /usr/local/apache2/htdocs
      readOnly: true
    ports:
    - containerPort: 80
      protocol: TCP
  volumes:
  - name: html
    hostPath:
       path: /var/htdocs
       type: Directory
```

# 4. Network Storage

## 4.1 GCE Persistance Storage

gce-mongodb-pod.yaml

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: mongodb
spec:
  containers:
  - image: mongo
    name: mongodb
    volumeMounts:
    - mountPath: /data/db
      name: mongodb
  volumes:
  - name: mongodb
    gcePersistentDisk:
      pdName: mongodb
      fsType: ext4
```

## 4.2 NFS 네트워크 볼륨

nfs-httpd.yaml 

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nfs-httpd
spec:
  containers:
  - image: httpd
    name: web
    volumeMounts:
    - mountPath: /usr/local/apache2/htdocs
      name: nfs-volume
      readOnly: true
  volumes:
  - name:  nfs-volume
    nfs:
      server: 10.0.2.5
      path: /home/nfs
```

# 5. PV/PVC

클러스터의 스토리지를 사용할 수 있도록 제공해주는 리소스

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled%203.png)

mongo-pv-pvc-pod.yaml

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: mongodb
spec:
  containers:
  - image: mongo
    name: mongodb
    volumeMounts:
    - mountPath: /data/db
      name: mongodb
  volumes:
#Pod는 PVC를 사용
  - name: mongodb
    persistentVolumeClaim:
      claimName: mongo-pvc
---
# PVC 정의
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mongo-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: ""
---
# PV정의
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mongo-pv
spec:
  capacity:
    storage: 10Gi
  volumeMode: Filesystem
  accessModes:
  - ReadWriteOnce
  - ReadOnlyMany
  persistentVolumeReclaimPolicy: Retain
  gcePersistentDisk:
    pdName: mongodb
    fsType: ext4
```

# 6. StorageClass

PV를 직접 만드는 대신 사용자가 원하는 PV유형을 선택하도록 오브젝트 정의

사용할 디스크와 PV가 자동으로 생성

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled%205.png)

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled%206.png)

mongo-storage.yaml

```yaml
#Storage Class : kubectl get sc로 조회
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: storage
#프로비전에 사용할 플러그인 선택
provisioner: kubernetes.io/gce-pd
#프로바이더에게 전달될 매개변수
parameters:
  type: pd-ssd
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mongo-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: storage #PV일때는 공백이였으나 StorageClass는 name을 입력
---
apiVersion: v1
kind: Pod
metadata:
  name: mongodb
spec:
  containers:
  - image: mongo
    name: mongodb
    volumeMounts:
    - mountPath: /data/db
      name: mongodb
  volumes:
  - name: mongodb
    persistentVolumeClaim:
      claimName: mongo-pvc
```

# 7. rook-ceph 프라이빗 클라우드 스토리지클래스

- 온프레미스 환경에서 storage-class를 구성하는 도구
- ceph은 파일 스토리지를 가상화시키는 클러스터를 구성할 수 있는 소프트웨어
- 직접 설치하는 방법도 있지만 rook 패키지를 활용하면 쿠버네티스에서 보다 편리하게 ceph을 설치하고 관리 가능
- [쿠버네티스 가상스토리지(Ceph) 설치 - 다나와 기술블로그 (danawalab.github.io)](https://danawalab.github.io/kubernetes/2020/01/28/kubernetes-rook-ceph.html)

```bash

```


# 8. StatefulSet

- 애플리케이션의 상태를 저장하고 관리하는 데 사용되는 쿠버네티스 객체
- 디플로이먼트는 파드를 삭제하고 생성할 때 상태가 유지되지 않는 한계가 있음
- 스테이트풀셋으로 생성되는 파드는 영구 식별자를 가지고 상태를 유지

## 8.1 Headless Service

![Untitled](%EC%BF%A0%EB%B2%84%EB%84%A4%ED%8B%B0%EC%8A%A4%20%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80/Untitled%208.png)

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
	name: web
spec:
	selector:
		matchLabels:
			app: nginx
	serviceName: "nginx" #서비스 지정
	replicas: 3
	template:
		metadata:
			labels:
				app: nginx
		spec:
			terminationGracePeriodSeconds: 10 #종료요청 후 기다리는 시간, 종료되지 않으면 강제SIGKILL
			containers:
			- name: nginx
				image: k8s.gcr.io/nginx-slim:0.8
				ports:
				- containerPort: 80
					name: web
				volumeMounts: #영구스토리지를 연결하고자 하는 위치
				- name: www
					mountPath: /usr/share/nginx/html
			volumeClaimTemplates:
			- metadata:
					name: www
				spec:
					accessModes: ["ReadWriteOnce"]
					storageClassName: "my-storage-class"
					resources:
						requests:
							storage: 1Gi	
```
