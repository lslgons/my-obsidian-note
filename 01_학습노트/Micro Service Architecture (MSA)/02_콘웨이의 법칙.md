# 콘웨이의 법칙

소프트웨어 구조는 그 소프트웨어를 개발한 조직의 의사소통 구조를 반영한다.

기존 접근방식에 따라 기술전문성 기반의 IT팀을 구성할 경우 커다란 3계층 (UI,BP,DB) 어플리케이션이 구성됨

MSA형태의 구성이라면 MS집합을 한 팀에서 맡을 수 있도록 조직을 정비하여야 함

각 팀은 비즈니스 로직을 위한 언어나 프레임워크, 데이터베이스 기술을 보유하여야 함

# 일체형 어플리케이션의 분해

일체형으로 만들어진 어플리케이션을 공조 마이크로서비스로 분해할 때의 문제점

- 느린 전달 : 비즈니스 요구사항 변경 시 많은 MS에 영향을 주어 추가작업 발생
- 성능저하 : 여러 MS간의 요청이 오가므로 응답시간이 길어짐
- 일관성 없는 데이터 : MS별로 관련 데이터가 나누어 지므로 MS간의 데이터가 어긋남

## 도메인 주도설계 (DDD)

Domain-Driven Design

도메인 주도설계의 핵심개념 : **경계가 있는 컨텍스트 (Bounded Context)**

서브 시스템이나 특정 팀의 담당 업무와 같은 특정 모델을 정의하고 적용할 수 있는 경계를 명시
